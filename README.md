<h1 align="center">Rclone Mega</h1>
<p align="center">Windows-приложение для безопасного зеркального бэкапа локальных папок в MEGA через rclone.</p>
<p align="center"><a href="README.md">Русский</a> · <a href="README.en.md">English</a> · <a href="https://github.com/Frommer-droid/Rclone-Mega/releases/latest">Download / Скачать</a></p>

Rclone Mega дает графический интерфейс к `rclone sync`: подключает MEGA,
хранит список задач, сначала показывает dry-run, а потом запускает боевое
зеркалирование только после подтверждения. В обычном сценарии отдельная
установка rclone не нужна: исполняемый файл лежит в `vendor\rclone\rclone.exe`
и входит в сборку приложения.

## Возможности

![Сортировка задач](docs/screenshots/task-overview.png)

![Настройки задачи](docs/screenshots/task-settings.png)

- отдельный переключатель безвозвратного удаления файлов MEGA для каждой задачи;
- автоматическое исключение кешей Python и распространённых временных файлов;
- сортировка задач по имени, аккаунту, времени запуска, режиму, следующей попытке и статусу;

- импорт одного или нескольких MEGA remote из INI-файла учетных данных;
- локальный `rclone.conf` рядом с приложением, без зависимости от глобального
  профиля rclone;
- несколько задач синхронизации с отдельными локальными и облачными путями;
- общий список задач всех аккаунтов с колонкой «Аккаунт» и фильтром по remote;
- проверка доступности выбранного remote и отображение квоты облака;
- обязательный dry-run перед зеркалированием и подробное окно подтверждения;
- прокрутка длинного списка изменений в окне подтверждения с постоянно
  доступными кнопками действий;
- «Зеркалировать всё»: проверка всех включённых задач, общее подтверждение
  и последовательное зеркалирование по аккаунтам;
- плановые проверки по интервалу и по времени суток;
- системный трей, автозагрузка Windows и запуск сразу в трее;
- ограничение удалений через `max-delete`;
- опциональный `backup-dir` для удаляемых файлов;
- простые `Exclude`-правила и ordered-фильтры rclone для выбранных подпапок;
- встроенный журнал, статистика последнего запуска и русская локализация Qt.

## Быстрый старт

### Готовая сборка

1. Скачайте installer со [страницы последнего релиза](https://github.com/Frommer-droid/Rclone-Mega/releases/latest) и установите приложение.
2. Запустите `Rclone Mega.exe` из установленной или portable-папки.
3. Нажмите `Добавить Remote` и выберите INI-файл с учетными данными MEGA.
4. Нажмите `Проверить выбранный`, чтобы убедиться, что remote доступен.
5. Добавьте задачу вида `D:\Docs` -> `my-mega:PC/Docs`.
6. Сначала нажмите `Проверить`.
7. Если dry-run показывает ожидаемые изменения, нажмите `Синхронизировать`.

Для нескольких аккаунтов выберите `Все аккаунты` и нажмите `Зеркалировать всё`.
Программа проверит включённые задачи, покажет одно общее окно подтверждения
и затем обработает задачи каждого аккаунта по очереди. Переключать аккаунты
между запусками не требуется. В режиме отдельного аккаунта кнопка
`Зеркалировать аккаунт` запускает только его задачи.

### Запуск из исходников

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe .\rclone_mega.py
```

После подготовки окружения запускайте `Rclone Mega-run.cmd` в корне проекта.
Нажмите заголовок таблицы для сортировки; повторный клик меняет направление.

В VS Code выбирайте интерпретатор `.venv\Scripts\python.exe`. Если включаете
виртуальное окружение вручную, запускайте команды из корня репозитория.

## Как работает безопасность

`rclone sync` делает зеркало: файлы, которых нет в локальной папке, могут быть
удалены из облачного назначения. Поэтому приложение не запускает боевую
синхронизацию вслепую.

Перед sync приложение выполняет `rclone sync --dry-run --combined -`, показывает
список отличий, локальных новых файлов и будущих удалений, а затем просит
подтверждение. Для дополнительной защиты используйте:

- `max-delete = 0`, чтобы запретить удаления;
- `max-delete = 1..100000`, чтобы остановить задачу при слишком большом числе
  удалений;
- `max-delete = -1`, если нужно полное зеркало без лимита удалений;
- `backup-dir`, если удаляемые файлы надо сначала переносить в отдельную папку
  MEGA.

Пароль MEGA не сохраняется в `settings.json`. Он передается в `rclone obscure`
через stdin, а доступ хранится rclone в локальном `rclone.conf`.

## Настройка задач

Минимальная задача состоит из локальной папки и облачного назначения:

```text
D:\Docs -> account:PC/Docs
```

Remote выбирается из списка уже настроенных подключений. При добавлении
нескольких аккаунтов используйте INI-файл с секциями:

```ini
[account1@example.com]
password = <your-password>

[archive]
email = account2@example.com
password = <your-password>
2fa = <your-2fa-code>
```

Для email-секций имя remote создается из части email до `@`, если в секции нет
явной строки `remote = ...`.

Интервал `0 д. 0 ч. 0 мин.` означает ручной запуск без таймера. Если включить
`Привязать к времени`, плановая проверка будет идти около указанного времени
суток. Например, интервал `1 д. 0 ч. 0 мин.` и старт `03:00` дают ежедневную
проверку около `03:00` после первой ручной проверки задачи.

Когда плановая проверка находит изменения, приложение открывает общее окно
подтверждения. В нем можно выбрать отдельные задачи, запустить зеркалирование
для всех, отложить решение или временно отключить интервал.

## Фильтры rclone

Поле `Exclude` подходит для простых исключений, например:

```text
*.tmp
Thumbs.db
```

Для сценария "зеркалировать только выбранные подпапки" используйте поле
`Фильтры rclone`. Правила идут по порядку и применяются относительно локальной
папки задачи:

```text
+ /Нужная/**
+ /Ещё одна/**
```

Если в поле указаны только `+`-правила, приложение автоматически добавит
финальное правило `- /**`, чтобы все остальные подпапки не попадали в зеркало.
Если нужны более точные исключения, добавляйте явные `-`-правила сами.

## Файлы конфигурации

| Файл                                 | Назначение                                     |
| ------------------------------------ | ---------------------------------------------- |
| `settings.json`                      | настройки окна, MEGA-блока, задач и расписаний |
| `rclone.conf`                        | локальный конфиг rclone с настроенными remote  |
| `rclone-mega.log`                    | runtime-журнал приложения                      |
| `vendor\rclone\rclone.exe`           | встроенный rclone в исходниках                 |
| `_internal\vendor\rclone\rclone.exe` | встроенный rclone в PyInstaller-сборке         |

`settings.json`, `rclone.conf` и журналы не коммитятся. Installer staging также
очищается от runtime-файлов, чтобы личный конфиг MEGA не попадал в релиз.

## Сборка и релиз

Сборка onedir-папки PyInstaller (доверенный PATH описан в `DEVELOPER.md`):

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m PyInstaller ".\Build_Tools\Rclone Mega.spec" --workpath .\.release-work\build --distpath .\.release-work\dist
$env:RCLONE_DIST_DIR = '.\.release-work\dist'
.\.venv\Scripts\python.exe .\Build_Tools\post_build.py
```

Результат появляется в корне проекта как `Rclone Mega\`.

Релизные скрипты:

| Скрипт                         | Что делает                                      |
| ------------------------------ | ----------------------------------------------- |
| `Build_Tools\Rclone Mega.spec` | spec-файл PyInstaller                           |
| `Build_Tools\post_build.py`    | переносит готовую onedir-папку в корень проекта |
| `00_Move.pyw`                  | обновляет локальную portable-папку              |
| `00_CrRel.pyw`                 | собирает installer через Inno Setup             |

`00_CrRel.pyw` берет готовую portable-папку, очищает staging от runtime-файлов
(`settings.json`, `rclone.conf`, логи) и создает `Rclone Mega_vX.Y.Z_Setup.exe`
на рабочем столе.

`00_Move.pyw` копирует portable-сборку в `C:\Portable\Rclone Mega` по умолчанию.
Чтобы выбрать другую родительскую папку, задайте перед запуском переменную
`RCLONE_MEGA_PORTABLE_DIR`.

## Ограничения

- приложение не реализует `bisync`;
- приложение не работает напрямую через API MEGA;
- зеркалирование выполняется только через `rclone sync`;
- учетные данные MEGA остаются локальными и должны храниться в приватной
  резервной копии, если приложение переносится на другой компьютер.

## Исключения и удаление

Кеши `__pycache__`, `*.pyc`, `*.pyo`, `.pytest_cache`, `.ruff_cache`, `.mypy_cache`,
а также `Thumbs.db`, `.DS_Store`, `*.tmp`, `*.temp`, `*.swp` и `~$*` исключены
автоматически. Эти правила применяются и перед пользовательскими include-фильтрами.
Файлы, уже находящиеся в облаке под исключёнными путями, не удаляются.

Переключатель «Удалять безвозвратно» по умолчанию выключен. Если он включён,
MEGA удаляет файлы мимо корзины. При заданном `backup-dir` файлы перемещаются
в резервную папку. Перед зеркалированием всегда выполняется dry-run.

Разные задачи могут использовать разные MEGA remote в одном окне;
все задачи выполняются последовательно.
