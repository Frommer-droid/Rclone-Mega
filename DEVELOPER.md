# DEVELOPER.md

## Интерфейс и One Dark

Тема находится в `app/ui/theme/`: каноническая палитра из 27 токенов в
`colors.py`, плотность в `scale.py`, QPalette/QSS и `apply_theme()` в `styles.py`.
Точка входа применяет тему сразу после создания QApplication: Fusion, Tahoma
10 pt при коэффициенте 1.0. `app/ui/styles.py` оставлен совместимым импортом.
Значения цветов не задавать отдельно в компонентах; производные оттенки
добавлять только в DERIVED_COLORS. Основное действие — `primaryButton`,
сохранение — `success_btn`, удаление/остановка — `danger_btn`.

Главное окно отводит основное место задачам. «Настройки» раскрывает путь
rclone, диагностику, автозагрузку, запуск в трее и общий режим закрытия
приложений. Журнал переключается в шапке. Компактные действия строки:
проверка, синхронизация, остановка, история. Значки в `app/ui/icons.py`
рисуются Qt из собственных SVG-контуров, имеют подписи доступности, подсказки
и отключённое состояние. Порядок и идентификаторы задач не меняются.

При сужении таблицы скрывается сначала режим (<1100 DIP), затем следующий
запуск (<900), затем последний запуск (<760). Название задачи и действия
сохраняются; полные пути и сведения о запуске доступны в подсказке имени.
Шесть текстовых столбцов изменяют ширину перетаскиванием границ заголовков.
«Автоподбор» измеряет все строки и заголовки, задаёт ширины по содержимому
и изменяет ширину самого окна под таблицу с учётом отступов и рамок.
Высота сохраняется, ширина ограничена рабочей областью монитора; развёрнутое
окно возвращается в обычный режим. При старте сохранённый размер не меняется.
После явного автоподбора `window.task_columns_fit_content` включает пороги
скрытия вторичных столбцов по измеренной ширине вместо фиксированных DIP,
чтобы компактная таблица не скрывала уже поместившиеся столбцы.
Пустого остатка справа и горизонтального переполнения нет. Перетаскивание
границы меняет ширину столбца за счёт соседних столбцов, сохраняя общую ширину.
При изменении окна размеры перераспределяются по сохранённым пропорциям.
Веса в базовых DIP хранятся в `window.task_column_widths` (ключи `1`–`6`) и
сохраняются с задержкой штатным таймером геометрии/при закрытии. Нулевые
размеры от скрытия не сохраняются; скрытие не считается ручным изменением.
Столбцы флажков и действий фиксированы, чтобы элементы оставались доступными.
Редактор содержит вкладки «Папки», «Расписание», «Безопасность», «Фильтры»;
каждая прокручивается независимо, кнопки сохранения всегда снаружи.
Геометрия окон сохраняется прежним способом без изменения схемы настроек.

В «Настройки → Масштаб интерфейса» выбор 50–150% задаёт поправку к
автоматическому масштабу экрана. Стандартная модель в
`app/services/ui_scale_service.py`: база 2560×1440@96 DPI, auto 70–200% с
шагом 10; поправка −50..50 с шагом 10; итог 35–300% с шагом 5. Используются
`availableGeometry()` и `logicalDotsPerInch()` Qt; готовый процент повторно
через системный DPR не умножается. Ключи настроек: `ui_scale_mode="auto"`,
`ui_scale_delta_percent`, `ui_scale_percent`. Старый итоговый процент мигрирует
в поправку. Нормализация выполняется при чтении и сохранении.

`app/ui/ui_scale_runtime.py` применяет тему и метрики из неизменных базовых
значений (`ui_scale_overrides.py`): шрифты/QSS, отступы, min/max/fixed размеры,
значки, строки таблиц, разделители и дочерние окна. Один фильтр приложения
обслуживает появление новых диалогов и меню. Сигналы экрана/DPI/топологии
подключаются после появления оконного handle. На ручной выбор разрешён resize
основного окна и открытых диалогов в пределах экрана; на смену экрана/DPI
принудительного resize нет. Startup сохраняет приоритет восстановленной
геометрии. Повторное применение коэффициента не накапливает увеличение.

SVG флажка и стрелок списков в `app/ui/theme/assets/` нужны во время работы;
spec включает их в `app/ui/theme/assets` внутри frozen-папки. Не удалять
эту запись при сборке; `tool.setuptools.package-data` включает их в Python-пакет.
PNG в корне используется для README, ICO — для
окна, трея и встроенного значка EXE. После изменения исходников готовые
portable/EXE обновляются отдельной сборкой.

Дизайн и источники: [docs/ui-design.md](docs/ui-design.md).

## Закрытие приложений перед зеркалированием

В общей панели «Подключения rclone» есть галочка «Закрывать приложения на время
зеркалирования всех задач». Она сохраняется в корневом `pause_applications`
SettingsStore (по умолчанию false), применяется к каждой запускаемой задаче
через `RcloneRunner.pause_all_applications` и не переписывает индивидуальные
значения задач. Эффективный режим — global OR task, только для настоящего sync.
Отключение общей галочки возвращает поведение отдельных задач. Новое значение
влияет на следующие запуски, текущая синхронизация продолжает выбранный режим.

В редакторе задачи есть выключенная по умолчанию галочка «Закрывать приложения
на время зеркалирования» (`SyncTask.pause_applications`). Она действует только
для настоящего sync; dry-run и диагностика не закрывают приложения.
`app/services/process_pause.py` получает процессы текущей Windows-сессии через
скрытый PowerShell/CIM, выбирает exe внутри исходной папки и сохраняет пути,
командные строки, родительские PID и точные FILETIME запуска. Собственная папка,
Rclone Mega/rclone, текущий процесс, его предки и защищённые дочерние процессы
исключены. Windows Restart Manager запрашивает корректное завершение основных
приложений без RmForceShutdown; helpers отдельно не перезапускаются.

Если приложения остались, MainWindow показывает названия и пути с кнопками
«Повторить» и «Отмена». Повторная проверка не запускает sync до освобождения
папки. После успеха/ошибки/отмены/FailedToStart восстанавливаются исходные основные
приложения, включая закрытые вручную. Уже работающие экземпляры не дублируются;
параметры разных экземпляров сохраняются. Launcher берётся из командной строки,
рабочая папка запуска — папка launcher/exe. Несохранённые документы, положение
окон, произвольное прежнее cwd и прежнее состояние трея восстановить универсально
невозможно. Приложения с exe вне источника, использующие его данные, не выявляются.
При принудительном завершении Rclone Mega/выключении компьютера автоматическое
восстановление не гарантируется; список существует только в памяти.

Операции выполняются в QThread, runner остаётся busy до конца восстановления,
и новая команда очереди не стартует раньше него. При обычном выходе из GUI
сначала выполняется остановка и восстановление, затем закрывается программа.
Ошибка повторного запуска отражается в итоге и локальной истории команды.
Новых зависимостей нет; функциональность Windows-only.

## История отдельных запусков

В каждой строке задачи меню «Запуски» открывает последние пять запусков или
полную историю. `RunHistoryDialog` показывает время, режим, статус и вывод
выбранного запуска; кнопки «Сохранить .md» / «Сохранить .log» экспортируют
полный отчёт. Выполняющийся запуск можно просматривать и обновлять; экспорт
доступен после завершения. История начинается с новых запусков после обновления.

`app/core/run_history.py` пишет metadata JSON и журнал для каждого запуска
в `run-history/<hash task id>/` рядом с settings.json. Вывод поступает через
отдельный сигнал `RcloneRunner.raw_output`, включая статистику и строки,
не отображаемые в общем журнале. JSON-сообщения rclone преобразуются в читаемый
текст. Журнал записывается сразу на диск без накопления в памяти, просмотр
ограничен последними 256 KB, экспорт читает весь файл потоком. Автоматического
удаления отчётов нет. После перезапуска запись без завершения показывается как
прерванная. Ошибка записи не останавливает синхронизацию и видна в общем журнале.

Отчёт включает версию приложения, пути, команду (без содержимого rclone.conf),
код завершения, статистику и конкретные ошибки. При ненулевом exit code runner
сохраняет последнюю ошибку rclone в summary, вместо одного кода завершения.
История исключена из Git, не включается в публичную поставку и добавлена
во встроенные исключения синхронизации, чтобы приложение не копировало свои
активные отчёты при зеркалировании папки portable-программ.

## Назначение

Этот файл описывает архитектуру, окружение и команды разработки приложения `Rclone Mega`.

## Окружение

- Python 3.12.
- Проектное `.venv`.
- Зависимости не устанавливать в глобальный Python.
- VS Code должен использовать `.venv\Scripts\python.exe`; не запускать исходники глобальным Python.
- Qt/PySide6 должен загружать русскую локализацию `qtbase_ru.qm` до создания окон.
- `rclone` должен запускаться отдельным процессом через `QProcess`.
- Встроенный runtime rclone лежит в `vendor\rclone\rclone.exe` в исходниках и в `_internal\vendor\rclone\rclone.exe` в PyInstaller onedir.
- Приложение всегда передает rclone локальный config через `--config <app_root>\rclone.conf`.
- Несколько аккаунтов и облачных подключений реализуются через несколько remote
  в одном локальном `rclone.conf`; несколько копий `rclone.exe` для этого не нужны.

Команды:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable)"
```

## Запуск

Из исходников: `Rclone Mega-run.cmd` в корне проекта. Ярлык разработки находится
в каталоге избранного разработчика, его рабочая папка — корень проекта.

```powershell
.\.venv\Scripts\python.exe .\rclone_mega.py
```

## Архитектура

```text
app/
  core/
    app_config.py
    localization.py
    logging_config.py
    settings_store.py
  models/
    sync_task.py
  services/
    rclone_config.py
    rclone_runner.py
  ui/
    main_window.py
    task_dialog.py
    styles.py  # совместимый импорт
    icons.py
    theme/     # colors.py, scale.py, styles.py, assets/
```

Корневой launcher должен оставаться тонким. Бизнес-логику, формирование аргументов `rclone` и работу с `QProcess` не размещать в `ui/`.
Windows-автозагрузка вынесена в `app/core/autostart.py`: путь Startup получать через `SHGetKnownFolderPath`, ярлык создавать через временный VBS без `pywin32`.

Таблица задач сортируется нажатием на заголовки «Задача», «Аккаунт»,
«Последний запуск», «Режим», «Следующий запуск» и «Статус».
Первый клик сортирует по возрастанию,
повторный меняет направление; стрелка показывает текущий порядок. Текст
сравнивается без учёта регистра, даты — по времени, а не отображаемой строке.
При сортировке дат текстовые состояния и пустые значения образуют отдельную
группу. Первый заголовок по-прежнему включает/отключает все видимые задачи.
Сортировка действует в текущем сеансе и сохраняется при обновлении таблицы
и фильтрации аккаунтов. Она применяется к копии видимого списка до заполнения
`QTableWidget`, не меняет `self.tasks`, настройки и порядок очереди выполнения.
Выбор и действия строки привязаны к ID задачи; встроенная сортировка Qt
отключена, чтобы заполнение строк с кнопками не перемещало их частично.

## Хранение данных

- `settings.json` лежит рядом со скриптом/exe.
- `rclone.conf` лежит рядом со скриптом/exe и не коммитится.
- В `settings.json` хранятся:
  - геометрия окна;
  - геометрия диалога подтверждения зеркалирования (`confirm_dialog`) и диалога задачи (`task_dialog`): один раз установленное положение/размер восстанавливается при каждом показе;
  - состояние раскрытия журнала и размер вертикального разделителя;
  - путь к `rclone.exe` и флаг явного внешнего rclone;
  - список известных remote, последний выбранный remote и `show_all_accounts`
    (общий список по умолчанию; реальное имя remote хранится отдельно);
  - список задач синхронизации.
- Секреты и логин MEGA не хранятся в проекте: приложение опирается на уже настроенный `rclone.conf`.
- Пароль MEGA не хранится в `settings.json`; при настройке remote он передается в `rclone obscure` через stdin, затем сохраняется rclone в `rclone.conf` в obscured-виде.
- Опциональный файл учетных данных для заполнения формы MEGA имеет INI-формат
  с секциями `[remote_name]`, полями `email`/`user`, `password`/`pass` и
  необязательным `2fa`. Приложение читает этот файл только по выбранному пути
  в момент настройки remote и не сохраняет путь или пароль в `settings.json`.
  Локальный шаблон может лежать в игнорируемой `.venv\mega_credentials.txt`.

## Модель задачи

Все задачи автоматически используют `DEFAULT_EXCLUDES` из `rclone_runner.py`:
`__pycache__/**`, `*.pyc`, `*.pyo`, `.pytest_cache/**`, `.ruff_cache/**`,
`.mypy_cache/**`, `Thumbs.db`, `.DS_Store`, `*.tmp`, `*.temp`, `*.swp`, `~$*`.
Встроенные и пользовательские исключения передаются через `--filter` перед
разрешающими правилами, без смешивания с `--exclude`. Повторы исключений удаляются.
Правила действуют при dry-run и sync, включая существующие задачи без изменения
их настроек. Флаг `--delete-excluded` не используется: ранее загруженные исключённые
файлы в облаке сохраняются. `.venv`, `.git`, `build`, `dist`, журналы и резервные
копии автоматически не исключаются.

`SyncTask` хранит:

- `id`, `name`, `source_path`, `remote_path`;
- `enabled`, `dry_run_first`;
- `hard_delete` — безвозвратное удаление в MEGA, по умолчанию `false`, включая старые задачи без этого поля. Runner явно передаёт `--mega-hard-delete=true/false`, переопределяя настройку remote. Dry-run ничего не удаляет; при активном `backup-dir` файлы перемещаются в резервную папку. Изменение режима сбрасывает результаты предыдущей проверки.
- `use_backup_dir`, `backup_dir`, `excludes`, `filter_rules`, `interval_minutes`, `scheduled_time`;
- runtime-поля последнего запуска: режим, время, статус, summary и число потенциальных удалений.

Количество и суммарный объём удалений не ограничиваются. Runner явно передаёт
`--max-delete -1 --max-delete-size off` для dry-run и sync, перекрывая переменные
окружения; Runner удаляет RCLONE_MAX_DELETE/RCLONE_MAX_DELETE_SIZE из
окружения дочернего процесса, поскольку rclone может применять env для
значения флага, совпадающего с default. Старые поля `max_delete`/`max_delete_size` игнорируются при загрузке
и не сохраняются. В интерфейсе нет настройки лимита.

`excludes` остаётся простым списком `rclone --exclude` для обычных исключений. Если в задаче заданы `filter_rules`, приложение не смешивает `--exclude` и `--filter`: старые `excludes` преобразуются в правила `- pattern`, а затем передаются пользовательские ordered filter rules в заданном порядке. Для сценария "зеркалировать только разрешённые подпапки внутри выбранной локальной папки задачи" пользователь указывает только правила вида `+ /Нужная/**`; если все `filter_rules` являются include-правилами, приложение автоматически добавляет финальное `- /**`.

Если пользователь меняет источник, назначение, exclude/filter или параметры удаления, задача снова требует dry-run.
`remote_path` и `backup_dir` должны быть обычными rclone-путями вида
`remote_name:folder/subfolder`; проверка больше не должна быть привязана только
к имени `mega:`.

## Runtime

- `settings.json` создается рядом с entrypoint/exe.
- Геометрия окна сохраняется при закрытии и автоматически (debounce) при перемещении/изменении размера; геометрия диалогов `confirm_dialog`/`task_dialog` сохраняется при закрытии диалога и восстанавливается при следующем показе с clamp к доступной геометрии экрана.
- Главное окно сохраняет Base64 `QWidget.saveGeometry()` в `window.geometry` и восстанавливает через `restoreGeometry()` с учётом рамки, состояния maximized и доступных экранов. Старые настройки без этого поля читаются через `resize()`/`move()`. Резервные координаты и позиции диалогов сохраняются через `pos()`, поскольку `geometry().topLeft()` исключает рамку и вызывает накопление смещения при восстановлении через `move()`.
- Лог очищается при каждом запуске.
- Память журнала ограничена: последние 2000 блоков, до 2048 символов
  на сообщение, без undo/redo и переноса длинных строк. Скрытый журнал
  подчиняется тем же пределам (`app/core/memory_limits.py`).
- Dry-run хранит не более 100 примеров изменений на задачу (до 2048 символов
  каждый). Полные счетчики считаются независимо от выборки и используются
  в подтверждении зеркалирования. Статистика rclone остается итоговым
  источником счетчиков; fallback использует максимум счетчиков combined и
  JSON-сообщений, чтобы не считать файл дважды. Старые списки в settings.json
  ограничиваются при загрузке и сохранении без изменения параметров задач.
- Runner освобождает собранные данные после завершения. Диагностический
  вывод ограничен 1 MiB символов, незавершенная строка — 65536 символами.
  Превышение этих пределов отмечает результат как неполный/неуспешный;
  такой dry-run не допускает автоматического перехода к подтверждению sync.
- `logo.ico` лежит в корне проекта и используется как иконка окна/панели задач; при сборке его нужно включать в runtime-ресурсы.
- Стандартные контекстные меню Qt должны быть на русском.
- Трей создается через `QSystemTrayIcon`; меню трея должно содержать открытие окна и штатный выход. Пункт `Свернуть в трей` показывать только когда окно сейчас открыто.
- На Windows правый клик по нативной кнопке закрытия окна обрабатывается через `nativeEvent` (`WM_NCRBUTTONUP`, `HTCLOSE`) и сворачивает окно в трей. Левый клик по крестику остается штатным закрытием.
- Таблица задач показывает компактную сводку без путей источника, назначения и интервала; эти данные доступны в деталях задачи. Таблица содержит колонку `Следующая попытка` с ближайшим плановым dry-run и колонку `Действия` с кнопками строки: `Проверить`, `Синхронизировать`, `Остановить`. Под таблицей общие действия должны оставаться отдельными кнопками: `Проверить все`, `Синхронизировать все`, `Остановить все`.
- Блок подключения показывает список известных remote. `Добавить Remote`
  выбирает INI-файл учетных данных и пакетно создает или обновляет все MEGA
  remote из секций файла в локальном `rclone.conf`; путь к INI и пароли не
  сохраняются в `settings.json`. После импорта приложение запускает проверку
  добавленных remote. При штатном старте приложение читает список remote из
  `rclone.conf` и последовательно проверяет уже настроенные подключения без
  повторного запроса учетных данных. `Проверить выбранный` запускает диагностику
  только для текущего remote. Верхний список remote является фильтром рабочей
  области задач: таблица, чекбокс заголовка, `Проверить все` и
  `Синхронизировать все` работают только с задачами выбранного remote. Диалог
  задачи выбирает remote только из уже настроенных подключений и сохраняет
  полный путь `remote:...`; произвольные remote-имена из поля пути не принимать.
  Не создавать синтетический remote `mega` по умолчанию: если INI содержит
  `[account@example.com]`, remote должен называться `account`, если только в
  секции явно не задано `remote = ...`.
- Справа от выбранного remote показывать квоту облака через `rclone about
  <remote>: --json`: `used / total` и процент в `QProgressBar`. Если backend не
  возвращает `total`, показывать только занятый объем; если команда недоступна
  или завершилась ошибкой, показывать `Квота: ошибка/недоступна`. Запрос квоты
  выполнять через общий `QProcess` runner, а не синхронный subprocess; обновлять
  при выборе remote, импорте remote, startup-проверке и успешном sync.
- Журнал скрыт по умолчанию и раскрывается checkable-кнопкой `Показать журнал` в верхнем блоке MEGA. При ручном раскрытии окно увеличивается вниз, чтобы текущая высота блока задач не уменьшалась; после раскрытия `QSplitter` работает как обычный разделитель. Состояние хранится в `window.log_visible`; размеры `content_splitter_sizes` сохраняются только когда журнал раскрыт.
- Массовый запуск задач выполняется строго последовательно.
- После ошибки или ручной остановки очередь задач очищается.
- Задачи по таймеру запускаются только после первого ручного запуска/проверки задачи, чтобы приложение не синхронизировало новые задачи сразу после старта.
- Плановый таймер, `Проверить` и `Проверить все` запускают dry-run через общий сценарий подтверждения. Если изменений нет, задача получает статус `Без изменений` и подтверждение sync не показывается. Если изменения есть, задачи накапливаются в общем окне подтверждения со списком задач, выбором отдельных задач, деталями dry-run из `--combined -`, кнопкой `Зеркалировать все`, кнопкой `Отложить` и кнопкой `Отключить интервал`.
- Команды rclone для GUI не должны использовать `-P`/`--progress` вместе с `--combined -`: progress-строки вида `* file: checking` попадают в stdout и могут быть похожи на combined-строки. Для обновления статистики использовать JSON-лог и `--stats 1s`; итоговые `stats.transfers/deletes/deletedDirs/renames/serverSide*` являются финальным фильтром ложных dry-run изменений. Combined-строки `= path` означают совпавшие файлы и не выводятся в журнал.
- Интервал в UI выбирается списками дней, часов и минут, но в модели и `settings.json` хранится прежнее поле `interval_minutes`.
- Опциональное поле `scheduled_time` хранится как `HH:MM`; если оно задано, плановый запуск привязывается к этому времени и повторяется с шагом `interval_minutes` после последнего ручного/планового запуска.
- Временное отключение интервала хранится отдельно в `interval_paused`; оно не сбрасывает `interval_minutes` и включается обратно из диалога задачи.

## Сборка И Релиз

- Локальная release-сборка выполняется через проектный Python и `-m PyInstaller`.
- `--workpath` и `--distpath` направлять в внешний временный каталог проекта.
  Перед post-build задать `RCLONE_DIST_DIR` на используемый dist-каталог.
  Кеши и work-каталоги post-build сохраняет; автоматического удаления нет.
- Installer staging: `RCLONE_RELEASE_WORKDIR` либо
  подкаталог `installer` внешнего временного каталога проекта; Inno Setup искать сначала в
  путь к установленному `ISCC.exe` (можно задать `INNO_SETUP_ISCC`).
- Основной spec-файл: `Build_Tools\Rclone Mega.spec`.
- Сборка должна быть `onedir`, а `qtbase_ru.qm` должен включаться в runtime как data-файл в `translations\qtbase_ru.qm`.
- `Build_Tools\post_build.py` обязан переносить итоговую папку в корень проекта как `Rclone Mega\` и копировать туда `VERSION`, `logo.ico` и корневой `settings.json` как есть.
- `Build_Tools\Rclone Mega.spec` обязан включать `vendor\rclone` в onedir-сборку.
- Перед `Analysis` spec заменяет унаследованный `PATH` минимальным доверенным
  набором путей проекта, Python и `System32`. Сборка аварийно завершается, если
  `Analysis.binaries` содержит файл за пределами проекта, `sys.prefix`,
  `sys.base_prefix` или Windows; корневые MSVC DLL должны происходить из
  текущего runtime PySide6.
- Проверка MSVC runtime учитывает полный путь назначения DLL: наличие копии в `PySide6\` не заменяет обязательный полный комплект в корне `_internal`.
- `Build_Tools\post_build.py` обязан проверять наличие `_internal\vendor\rclone\rclone.exe` в итоговой папке.
- `00_CrRel.pyw` не должен включать runtime `rclone.conf` в installer staging.
- В `vendor\rclone` должен оставаться license notice для встроенного rclone.
- `00_Move.pyw` обновляет portable-папку в `C:\Portable\Rclone Mega`.
- Перед заменой portable-папки `00_Move.pyw` сохраняет существующий
  `rclone.conf` и восстанавливает его в новой сборке; при первом переносе
  используется корневой `rclone.conf`, если он существует.
- `00_CrRel.pyw` собирает installer через Inno Setup из уже подготовленной portable-папки.
- Installer показывает отмеченную по умолчанию галочку запуска приложения после
  интерактивной установки (`nowait postinstall skipifsilent`), но release-скрипты
  не запускают установщик или собранное приложение сами.

Commit, tag, push и GitHub Release выполнять только по явному запросу.


## Очередь проверки отмеченных

`_ordered_visible_tasks()` задаёт единый порядок таблицы и массовой проверки.
`CheckBatch` фиксирует IDs и результаты в момент нажатия, учитывая аккаунт и
enabled. Уже выполняющиеся/ожидающие задачи не дублируются и учитываются как
пропущенные. Ошибка dry-run в этой партии не очищает очередь. Отсутствующий
источник и отмена считаются пропуском. Прогресс показывает исходный номер/общее
число; итог в status_label и журнале. «В очереди» — отображение, а не сохранённый
runtime-статус. Общая проверка по-прежнему собирает единое подтверждение sync.


Остановка партии во время диагностики аккаунта откладывает финализацию до
terminal signal rclone. Обработчики завершения как задачи, так и диагностики
вызывают `_finish_check_batch_if_done()`. Если executable отсутствует, очередь
и партия отменяются вместе через `_cancel_check_batch()`; кнопка разблокируется.
